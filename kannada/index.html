01 · Start with Java

What happens to Java code?

You write instructions in a .java source file. The Java compiler turns them into bytecode. The Java Virtual Machine (JVM) runs that bytecode.

Hello.javaSource code
javacJava compiler
Hello.classBytecode
JVMRuns bytecode
Hello WorldProgram output

For a tiny program, you can compile and run it directly—no Maven project is needed.

Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
Run these commands from the folder containing Hello.java
javac Hello.java
java Hello

In simple words: javac translates your source code; java starts the JVM to run the compiled program.

02 · Build with Maven

Why use Maven?

As a project grows, it can have many Java files, libraries, tests and resources. Maven helps manage dependencies and repeat common build steps. Its pom.xml file describes the project and its build configuration.

Without a build tool

  • Compile files and manage class paths yourself.
  • Download and track libraries manually.
  • Repeat build and test steps by hand.

With Maven

  • Declare libraries in pom.xml.
  • Use shared commands for compile, test and package.
  • Keep a consistent build that can be automated.
mvn clean

Removes previous build output, usually the target folder.

mvn compile

Compiles the project's main source code.

mvn test

Runs the tests configured for the project.

mvn package

Builds a distributable package, commonly a JAR or WAR.

mvn install

Builds the project and places its artifact in your local Maven repository for other local projects to use.

mvn deploy

Publishes the artifact to a remote repository configured for the project.

A common local build
mvn clean package

Remember: this cleans old output, then compiles, tests and packages the project. It does not start the application. You also do not need mvn install just to run your app.

The finished artifact is usually created under target/. A plain JAR is not automatically runnable with java -jar; that depends on how the project is packaged and configured.

04 · Run it on a server

Can your laptop host an application?

Yes. For learning, you can run a Java web application on your laptop and open it in a browser. But “running locally” and “available to everyone on the internet” are different things.

Know the server roles

  • A Java web app often runs with an embedded server such as Tomcat, or on a separately installed application server.
  • Apache HTTP Server can serve static files or sit in front of an app as a reverse proxy when configured.
  • Apache HTTP Server does not automatically run every Java application by itself.

Know who can reach it

  • localhost usually means the app is reachable from that same laptop.
  • Other devices on your home network may need your laptop's network address and suitable app/firewall settings.
  • Public access needs additional network, security and availability setup.

Why a laptop is not ideal for a 24/7 service

A laptop can sleep, lose power or internet, restart for updates, or change network address. It may also be exposed to security risks if opened to the public internet. For a service that must stay available, teams typically use a server, VPS or cloud platform with proper monitoring and security.

Day 1 takeaway: your laptop is great for learning and local testing. Hosting a reliable public service is a separate step—and we’ll build on these ideas in later lessons.

05 · Check your understanding

What does mvn clean package do?

Choose the best answer before opening the explanation:

  1. It removes old build output, builds and tests the project, then creates a package.
  2. It only downloads libraries into the local Maven repository.
  3. It automatically starts the Java application.
  4. It installs Maven on your computer.
Show the answer and explanation

Correct answer: 1. Maven cleans the previous output, then runs the build lifecycle through the package phase. That includes compiling and running configured tests before creating the JAR or WAR.

It does not start the app. To run it, use the method configured by that project. Also, mvn install is a separate lifecycle step that puts the artifact in your local Maven repository.
